# 決定の一覧

Sendo で決めたことを、テーマごとに1ファイルで置く。各ファイルには今の決定だけを書き、経緯は git の履歴で追う。残し方は [documentation.md](documentation.md) を参照。

| テーマ | 状態 | 概要 |
|---|---|---|
| [決定の残し方](documentation.md) | 提案中 | テーマごとに1ファイルを書き換える。履歴は git が持つ |
| [テックスタック](tech-stack.md) | 提案中 | TypeScript ＋ Hono。第1版は Cloudflare 前提で、緩衝層を挟む |
| [ユーザーと認証](accounts.md) | 提案中 | ユーザーの表を持ち、パスワードは持たない。ログインは自前の OpenID Connect（Google など、1 人が複数の提供元を持てる）、許可したメールだけ。データは人ごと |
| [差分同期](sync.md) | 提案中 | 人ごとのデータに書き込み順の変更番号を振り、1 回のリクエストで差分を取る。消したものは印と記録で伝える |
| [Google Reader API 互換](greader.md) | 提案中 | パスワードはアクセストークン。アイテムの ID は記事に持たせる乱数の整数。処理は REST API と同じものに任せる |
| [MCP サーバー](mcp.md) | 提案中 | `/mcp` にセッションなしで置く。MCP 用のトークンか OAuth で使い、許可の画面は sendo-reader に置く。スコープは read と write。記事は信頼できないデータとして返す |
| [仕事の流し方](jobs.md) | 提案中 | 取得などの仕事を、キューの封筒に最大 10 個束ね、`ctx.exports` で 1 つずつ別の実行で動かす。取得の間隔は設定で変える。Rust の Wasm は CPU が上限になってから |
| [デプロイ](deploy.md) | 提案中 | 各自が fork し、Workers Builds でつなぐ。デプロイの手順（マイグレーションを先に。D1 がまだなければデプロイを先に）は `package.json` に書く。D1 と Queues の ID はリポジトリに書かない。人ごとの設定は画面の変数に置く（`keep_vars`）。上流の更新を自動で取り込むなら、sendo-updater も fork する（毎分、差分を見て取り込む） |
| [古い記事の片付け](retention.md) | 提案中 | スターのない記事は、取り込んでから 90 日で消す（未読でも）。フィードに載っている間は記事の行を残し、入り直しを防ぐ。受信箱の消した記録は 30 日で消す |
| [画像の中継とサムネイル](images.md) | 提案中 | sendo が署名した URL の画像だけを、`/api/v1/images` で中継する（reader の CSP は変えない）。SVG は通さない。記事のサムネイルとフィードのアイコンを、中継の URL で配る |
| [クライアントの設定](settings.md) | 提案中 | reader の設定を、ユーザー × 端末の種類（`mobile` ／ `desktop`）ごとに、名前と JSON の値の組で預かる。中身は解釈しない。差分同期で配り、消した項目は印で伝える |
| [記事の本文](content.md) | 提案中 | フィードに入っている本文をサニタイズして R2 に置き、記事ごとに配る（差分同期には載せない）。本文の中の画像は中継の URL に書き換える。記事のページから抜くのは、読者が開いたときで、そのあとに作る |

経緯を知りたいとき：

```sh
git log -p -- docs/decisions/<テーマ>.md
```
