# 決定の一覧

Sendo で決めたことを、テーマごとに1ファイルで置く。各ファイルには今の決定だけを書き、経緯は git の履歴で追う。残し方は [documentation.md](documentation.md) を参照。

| テーマ | 状態 | 概要 |
|---|---|---|
| [決定の残し方](documentation.md) | 提案中 | テーマごとに1ファイルを書き換える。履歴は git が持つ |
| [テックスタック](tech-stack.md) | 提案中 | TypeScript ＋ Hono。コンテナ（Node ＋ SQLite）だけで動かし、Cloudflare では動かさない。実行環境の入出力は緩衝層にまとめる。重い処理は Rust で書き、napi-rs で読み込む |
| [ユーザーと認証](accounts.md) | 提案中 | ユーザーの表を持ち、パスワードは持たない。ログインは自前の OpenID Connect（Google など、1 人が複数の提供元を持てる）、許可したメールだけ。データは人ごと |
| [Discord チャンネルの購読](discord.md) | 提案中 | Bot で選んだチャンネルの新着を取り込み、接続ごとに保存する |
| [差分同期](sync.md) | 提案中 | 人ごとのデータに書き込み順の変更番号を振り、1 回のリクエストで差分を取る。消したものは印と記録で伝える |
| [あとで読むページ](saved.md) | 提案中 | 購読の有無を問わず URL を人ごとに保存し、同じアカウントの端末へ差分同期する |
| [Google Reader API 互換](greader.md) | 提案中 | パスワードはアクセストークン。アイテムの ID は記事に持たせる乱数の整数。処理は REST API と同じものに任せる |
| [MCP サーバー](mcp.md) | 提案中 | `/mcp` にセッションなしで置く。MCP 用のトークンか OAuth で使い、許可の画面は sendo-reader に置く。スコープは read と write。記事は信頼できないデータとして返す。購読一覧と今日の未読は Resources でも返す |
| [記事を開いた履歴](activity.md) | 提案中 | reader で開いた記事を人ごとに記録し、MCP から日時と操作元で探せるようにする |
| [仕事の流し方](jobs.md) | 提案中 | 取得などの仕事を SQLite のジョブの表に積み、同じプロセスで同時に 4 つまで動かす。1 つの仕事が扱う量に上限を置く。取得の間隔は、記事の出るペースからフィードごとに決める（設定の間隔が下限、1 日が上限）。429 ／ 503 の `Retry-After` を上限付きで反映する。長く失敗しているフィードは週 1 回取得し、購読の API で状態を返す |
| [フィードの移転先候補](feed-relocation.md) | 提案中 | 404 や解析失敗の応答のリンクから確認済みの候補を 1 件返す。読者が新しい購読として追加する |
| [コンテナ版](container.md) | 提案中 | Sendo を動かす唯一の形。すべての機能を載せる。Node ＋ SQLite（libsql）で、1 つのコンテナ・1 つのプロセスで動かす。重い処理は Rust で、読み込めなければ起動しない。既存のサーバー（RustXNG など）と画面（sendo-reader）は別のコンテナで並べ、画面・API・認証は sendo-reader から公開する。X の埋め込みを有効にするときは、専用の静的ファイルを別 HTTPS ホストで配信し、reader のイメージもビルドする。Sendo のイメージは上流の CI が GHCR に置き、標準構成では使う人は fork しない。マイグレーションは起動時に当てる。接続する IP も確かめて SSRF を防ぐ |
| [保存容量と古い記事の片付け](retention.md) | 提案中 | 保存容量を env で設定し、空きがある限り記事を残す。言語判定結果と検索索引も容量に含める。圧迫時は古いスターなし記事から削除。スターとフィード掲載中の記事は保護し、削除記録は 30 日残す |
| [画像の中継とサムネイル](images.md) | 提案中 | sendo が署名した URL の画像だけを、`/api/v1/images` で中継する（reader の `img-src` は広げない）。SVG は通さない。記事のサムネイルとフィードのアイコンを、中継の URL で配る |
| [クライアントの設定](settings.md) | 提案中 | reader の設定を、ユーザー × 端末の種類（`mobile` ／ `desktop`）ごとに、名前と JSON の値の組で預かる。中身は解釈しない。差分同期で配り、消した項目は印で伝える |
| [記事の本文](content.md) | 提案中 | フィードに入っている本文をサニタイズしてファイルに置き、記事ごとに配る（差分同期には載せない）。本文の中の画像は中継の URL に書き換え、フィードと抽出本文の X の引用の印を保持する。ページからは冒頭に分かれた X の引用や Imgur の画像も抜く。記事のページからも本文を抜く（Rust。元の DOM を残して本文を判定し、本文の画像ページを上限付きで調べる。サイト別の設定は持たない）。取り込んだときに抜き、サニタイズした HTML を DB の別の表に持つ。ページは同じホストへ 1 本ずつ取りにいき、robots.txt を守る |
| [記事の言語判定](article-language.md) | 合意済み | Lingua 通常モードで主言語を判定し、入力元ごとに別表へ保存する。短文と不確実な結果は保留。比較・コンテナ・保存の検証結果と限界を根拠として残す |
| [記事のキーワード検索](article-search.md) | 提案中 | SQLite FTS5 と trigram で、受信箱の記事をタイトル・要約・本文から探せるようにする |
