# 決定の一覧

Sendo で決めたことを、テーマごとに1ファイルで置く。各ファイルには今の決定だけを書き、経緯は git の履歴で追う。残し方は [documentation.md](documentation.md) を参照。

| テーマ | 状態 | 概要 |
|---|---|---|
| [決定の残し方](documentation.md) | 提案中 | テーマごとに1ファイルを書き換える。履歴は git が持つ |
| [テックスタック](tech-stack.md) | 提案中 | TypeScript ＋ Hono。コンテナ（Node ＋ SQLite）だけで動かし、Cloudflare では動かさない。実行環境の入出力は緩衝層にまとめる。重い処理は Rust で書き、napi-rs で読み込む |
| [ユーザーと認証](accounts.md) | 提案中 | ユーザーの表を持ち、パスワードは持たない。ログインは自前の OpenID Connect（Google など、1 人が複数の提供元を持てる）、許可したメールだけ。データは人ごと |
| [Discord チャンネルの購読](discord.md) | 提案中 | Bot で選んだチャンネルの直近の投稿を取り込み、Gateway で新着を知って REST の取得を前倒しする。同時に行う同じ権限照会をまとめ、Bot REST のレート制限を守る。取得した投稿は接続ごとに保存する。投稿のテキストと埋め込みの文字を本文にし（全文としても返す）、サーバーのアイコン（なければ Discord のアイコン）をフィードのアイコンにする |
| [差分同期](sync.md) | 提案中 | 人ごとのデータに書き込み順の変更番号を振り、1 回のリクエストで差分を取る。消したものは印と記録で伝える。記事の翻訳が変わったら、その記事の受信箱の行に番号を振り直して届ける。人ごとの同期の対象が変わったら WebSocket で知らせる（利用者ごとに 1 秒まとめる。閉じるコードでクライアントの動きを分ける） |
| [ワークスペース](workspaces.md) | 提案中 | 所属とデフォルトの印を差分同期で届ける。アカウントごとに有効なデフォルトを1件持ち、所属先を省いた新規購読はそこに割り当てる。削除できるのはデフォルト以外で有効な購読が0件のもの |
| [あとで読むページ](saved.md) | 提案中 | 購読の有無を問わず URL を人ごとに保存し、同じアカウントの端末へ差分同期する |
| [Google Reader 互換 API の廃止](greader.md) | 提案中 | 日常の閲覧は公式 Reader。自作クライアントやスクリプトは REST API、エージェントは MCP を使う |
| [MCP サーバー](mcp.md) | 提案中 | `/mcp` にセッションなしで置く。MCP 用のトークンか OAuth で使い、許可の画面は sendo-reader に置く。スコープは read と write。記事は信頼できないデータとして返す。購読一覧と今日の未読は Resources でも返す。購読先を省くとデフォルトに追加する。ワークスペースの管理と、指定フォルダ内の購読の一括移動の契約を定める。通知のベルも読み書きできる |
| [記事を開いた履歴](activity.md) | 提案中 | reader で開いた記事を人ごとに記録し、MCP から日時と操作元で探せるようにする |
| [仕事の流し方](jobs.md) | 提案中 | 取得などの仕事を SQLite のジョブの表に積み、同じプロセスで同時に 4 つまで動かす。1 つの仕事が扱う量に上限を置く。取得の時刻は、記事の出る時刻の癖（毎日 x 時、n 時間おきなど）が見つかればそれに合わせ、なければ記事の出るペースからフィードごとに決める（設定の間隔が下限、1 日が上限）。定期実行は 5 分おき。言語の判定と訳すかどうかを決める仕事は、前の処理が終わったら記事ごとに積み、定期実行は取りこぼし、判定し直し、取り込んでから 1 時間たった記事を拾う。429 ／ 503 の `Retry-After` を反映し、停止状態でない Discord 購読の明示的な 429 待機は定期時刻と分ける。長く失敗しているフィードは週 1 回取得し、購読の API で状態を返す |
| [フィードの移転先候補](feed-relocation.md) | 提案中 | 404 や解析失敗の応答のリンクから確認済みの候補を 1 件返す。読者が新しい購読として追加する |
| [コンテナ版](container.md) | 提案中 | Sendo を動かす唯一の形。すべての機能を載せ、設定で有無が分かれる翻訳、Discord、Web Push は、それぞれの API で伝える。Node ＋ SQLite（libsql）で、1 つのコンテナ・1 つのプロセスで動かす。重い処理は Rust で、読み込めなければ起動しない。既存のサーバー（RustXNG など）と画面（sendo-reader）は別のコンテナで並べ、外には sendo-reader だけを出す。イメージは上流の CI が GHCR に置き、使う人は fork しない。更新は手で pull するのを基本にし、自動で更新したい人には、上流のスクリプトの例（CI の通った最新のコミットだけを上げる。sendo を上げる前にバックアップを取り、sendo のあとに sendo-reader を上げる。sendo が healthy にならなければイメージとバックアップを組で戻す）を勧める。マイグレーションは起動時に当てる。接続する IP も確かめて SSRF を防ぐ |
| [保存容量と古い記事の片付け](retention.md) | 提案中 | 保存容量を env で設定し、空きがある限り記事を残す。言語判定結果、検索索引、訳文も容量に含める。圧迫時は古いスターなし記事から削除。スターとフィード掲載中の記事は保護し、削除記録は 30 日残す |
| [画像の中継とサムネイル](images.md) | 提案中 | sendo が署名した URL の画像だけを、`/api/v1/images` で中継する（reader の CSP は変えない）。SVG は通さない。記事のサムネイルとフィードのアイコンを、中継の URL で配る |
| [クライアントの設定](settings.md) | 提案中 | reader の設定を、ユーザー × 端末の種類（`mobile` ／ `desktop`）ごとに、名前と JSON の値の組で預かる。中身は解釈しない。差分同期で配り、消した項目は印で伝える |
| [記事の本文](content.md) | 提案中 | フィードに入っている本文をサニタイズしてファイルに置き、記事ごとに配る（差分同期には載せない）。本文の中の画像は中継の URL に書き換える。記事のページからも本文を抜く（Rust。元の DOM を残して本文を判定し、本文の画像ページと Imgur の投稿のページを上限付きで調べ、同じ画像を重ねない。サイト別の設定は持たない）。取り込んだときに抜き、サニタイズした HTML を DB の別の表に持つ。ページは同じホストへ 1 本ずつ取りにいき、robots.txt を守る |
| [記事の言語判定](article-language.md) | 合意済み | Lingua 通常モードで主言語を判定し、入力元ごとに別表へ保存する。短文と不確実な結果は保留。比較・コンテナ・保存の検証結果と限界を根拠として残す |
| [記事の翻訳](translation.md) | 提案中 | 日本語以外の記事を Claude API で日本語に訳す。訳すかどうかは記事ごとに 1 回だけ決める。取り込んだ記事はバッチで自動で訳し、採用できなかった本文断片だけを保存前に上限付きで補う。まだ訳文のない記事は読む人が求めたときだけその場で訳し、求めれば 1 回だけ訳し直す。モデルと思考量は段階（通常 ／ 自動の翻訳の長文 ／ 品質優先。既定は Sonnet ／ Haiku ／ Opus）ごとに設定で選び、系列の最新を Models API で選ぶ。訳したときのモデル・思考量・段階・プロンプトの版・トークン数・写した元を残し、モデルと思考量は配る。HTML は LLM に渡さず、文の断片だけを送る。訳文は「だ・である」でそろえ、原文にないものを足さず、人名と概念の名前は原文を残して読みと意味を添える。訳文は記事ごとに 1 つで全員で使い回し、同じ元記事（正規化した URL が同じ）の記事どうしでは訳を写して、同じ原文をなるべく重ねて訳さない。状態と訳したタイトル、訳せなかった理由（拒否の種類など）は差分同期で配る。Discord の投稿は訳さない。API キーがあるときだけ動く |
| [記事のキーワード検索](article-search.md) | 提案中 | SQLite FTS5 と trigram で、受信箱の記事をタイトル・要約・本文から探せるようにする |
| [通知](notifications.md) | 提案中 | 購読か言葉（空白区切りの AND）、またはその両方に、人ごとのベルを付ける（既定はオフ。差分同期で配る）。取り込んだときにタイトル・要約・フィードの本文で判定し、ベルより前の記事と購読したばかりの初回の取得の記事には送らない。同じベルで 10 分に 4 件目からは 1 通にまとめ、1 人 1 時間 20 通まで。中身は Declarative Web Push の JSON にし（`tag` に記事の ID、`app_badge` に未読の合計）、RFC 8291 で暗号化して 4096 バイトに収める |
| [Web Push](web-push.md) | 提案中 | ベルの通知を、セッションに結んだ端末すべてに Web Push で送る（通知の行と端末ごとの仕事にし、取り込みと切り離す）。VAPID の鍵は sendo が作って DB に置き、`VAPID_SUBJECT` と `READER_URL` があるときだけ動く（有無は `GET /api/v1/push`）。送り先にも接続する IP の確かめを当てる |
