# Google Reader 互換 API の廃止

- 状態：提案中
- 関連：[インセプションデッキ](../inception-deck.md)、[ユーザーと認証](accounts.md)、[MCP サーバー](mcp.md)

## 決定

1. **Google Reader 互換 API を廃止する。** 対象は `/accounts/ClientLogin` と `/reader/api/0/...`。「好きなリーダーで読める」は製品の訴求から外す。
2. **日常の閲覧には公式の sendo-reader を使う。** 自作クライアントやスクリプトは REST API、エージェントは MCP から Sendo を使う。
3. **他のリーダーの優れた操作や読み方は、公式 Reader に取り込む。** 具体的な候補が見つかったら、sendo-reader の Issue で扱う。
4. エンドポイントを削除するまでは、稼働中の入口と廃止予定を [README の利用案内](../../README.md#リーダーアプリで読むgoogle-reader-api) に記載する。

## 理由

- 互換クライアントを使っている人はおらず、日常の閲覧はすでに公式 Reader で行っている。
- 互換 API は記事の要約を返す。翻訳やワークスペースなど Sendo 固有の機能が増えるにつれ、外部リーダーで見える情報や操作できる範囲と、公式 Reader での体験に差が開く。
- 互換のために認証、記事ごとの整数 ID、エンドポイントとテストを維持している。その工数を、日常的に使う公式 Reader の改善に振り向ける。

## 検討した代替案

- **現在の互換 API を維持する。** Reeder や NetNewsWire などをそのまま接続できるが、利用者がいない間も、記事の取り込みや購読の仕様を変えるたびに互換の挙動を確かめる必要がある。

## 見直す条件

- 公式 Reader や REST API では満たせない具体的な外部リーダー連携の需要が出たとき。
