# ワークスペース

- 状態：提案中
- 関連：[ユーザーと認証](accounts.md)、[差分同期](sync.md)、[あとで読むページ](saved.md)、[Google Reader 互換 API の廃止](greader.md)、[MCP サーバー](mcp.md)

## 決定

1. **ワークスペースはアカウントごとに持つ。** 購読は最大1つに所属し、`workspaceId` が null なら未割り当て。フォルダは従来どおり使い、同じフォルダ内でも購読ごとに所属を選べる。移動で購読・記事の ID、フォルダ、既読・スターは変わらない。過去の記事も現在の有効な購読の所属に従う。Reader の「すべて表示」には未割り当てと購読のない項目も含める。Reader は表示の選択を手元に持ち、アクセス権限はアカウント単位とする。
2. **アカウントごとに有効なワークスペース1件をデフォルトにする。** デフォルトは名前や購読数から独立して持つ。デフォルトを設ける移行では、初回に自動作成された有効なワークスペースを改名済みでも選ぶ。残っていなければ有効な中で最も古いもの（同時刻は ID 順）、有効なものが0件なら新しく作る `default` を選ぶ。既存購読は未割り当ても含めて現在の所属を保つ。新規アカウントではユーザーを挿入する文のトリガーで、デフォルトの印が付いた空の `default` を作る。切り替えは、指定先が本人の有効なワークスペースであることを確かめ、旧・新のデフォルトを一度に更新する。すでにデフォルトの項目を指定した場合も成功として返す。
3. **デフォルト以外で有効な購読が0件なら削除できる。** 削除の文でデフォルトの印と有効な購読の有無を確かめる。デフォルトの削除は 409 `workspace_is_default`、それ以外で有効な購読があれば 409 `workspace_not_empty` を返す。購読解除済みの行は件数に含めない。削除は変更番号を振って印を付け、フォルダと同様に同期用に保持する。
4. **REST API で管理する。** 入口はすべて `/api/v1` の下。ワークスペースは `id`、`name`、`createdAt`、`isDefault`（真偽値）を返す。名前は前後の空白を除いた1〜200文字で、有効なワークスペース内でアカウントごとに一意とする。

   | 操作 | リクエストと結果 |
   |---|---|
   | `GET /workspaces` | 有効なワークスペースを名前順で `{ items }` に返す |
   | `POST /workspaces` | `{ name, id? }` でデフォルトの印を付けずに作る。ID を省略するとサーバーで採番する。オフライン作成ではクライアント指定の小文字 UUID を使え、同じ有効な ID の再送は現在の項目を200で返す。新規は201で `{ workspace }` を返す |
   | `PATCH /workspaces/{id}` | `{ name }` で改名、`{ isDefault: true }` でデフォルトへ切り替え、どちらも200で `{ workspace }` を返す。1回のリクエストでどちらか一方を指定する |
   | `DELETE /workspaces/{id}` | デフォルト以外の空のワークスペースを削除して204を返す。同じ利用者が削除済みの ID を再送したときも204 |
   | `POST /feeds` ／ `PATCH /feeds/{id}` | 購読の入力に `workspaceId` を受ける。追加時は7に従う。変更時の省略は現在の所属を保ち、null は所属を外す。変更で `workspaceId` を渡すときは対象の購読の `subscriptionId` も渡す。購読し直した別の行への変更は404。対象の購読 ID と所属先を、指定された変更を書き込む文の中で確かめる |

   - 同じ名前との衝突は 409 `workspace_exists`。作成で削除済みまたは使用できない ID を指定すると 409 `workspace_id_taken`。変更・削除で本人の項目が見つからなければ404。購読の所属を変えるときに存在しない・削除済み・別アカウントのワークスペースを指定すると 400 `workspace_not_found` を返す。
   - `GET /feeds` と購読の追加・変更の応答に `workspaceId` と `subscriptionId` を載せる。購読し直すと `subscriptionId` は変わる。Discord の購読も、作成後は同じ変更 API で移動できる。
5. **差分同期は `includeWorkspaces=true` を指定したクライアントに届ける。** `workspaces` 配列に有効な項目（`deleted: false`、`isDefault` 付き）と削除の印（`id, deleted: true`）を返し、有効な購読に `workspaceId` と `subscriptionId` を付ける。デフォルトを設ける移行では印を付ける行に、切り替えでは印が変わる旧・新の行に変更番号を振る。変更番号とページ送りはワークスペースの表で独立させる。ワークスペースの位置を持たないカーソルでは、ワークスペースと購読を番号0から送り、購読に所属を補う。購読は通常の差分と同じ規則で送り、現在も有効な購読があるフィードには古い購読の削除の印を送らない。ほかの表はカーソルの続きから送る。指定を外したリクエストの応答ではワークスペースの位置を持たない。Reader は、所属情報が揃うまで選択外の記事を出さない。

   旧・新のデフォルトの変更は別ページに分かれることがある。Reader は差分の全ページを適用してからデフォルトの印を確定する。Reader は `workspaces` が付いた同期応答でワークスペース対応を確認する。7 の新規購読の割り当てに対応した Sendo は、`includeWorkspaces=true` の同期応答の最上位に `defaultWorkspaceOnSubscribe: true` を返す。差分が空のページにも付ける。Reader は接続先の同期応答でこの値を確認してから、購読の追加で所属先を省略できる。`isDefault` の有無とは独立に判定する。
6. **一括既読は、押したときの購読 ID と同期済みの境界を送る。** `POST /api/v1/articles/mark-read` で従来の範囲指定に加え、記事の位置が完了した `cursor` と `subscriptionIds` の組を受ける。他の範囲指定や `until` との併用は400。Reader は押したときに選択範囲へ入っていた有効な購読の ID を操作に記録する。送信時にその ID が指す同じ利用者の有効な購読だけを対象にするので、購読の移動で別の購読が加わらず、解除後に購読し直したものにも及ばない。現在のワークスペース名・所属はこの照合に使わない。従来と同じく `read_seq` と記事 ID で同期済みの境界を守る。1 回の上限は90件で、超える場合は同じカーソルで分けて送れる。公開日時や記事位置でさらに絞る操作は従来の個別記事 ID 指定を使う。
7. **所属指定のない新規購読はデフォルトに入れる。** REST API と MCP の購読追加は、`workspaceId` に本人の有効な ID を渡せば指定先、省略または null ならデフォルトに入れる。Discord の購読と OPML の取り込みで作る新規購読もデフォルトに入れる。追加を書き込む文の中で、明示された所属先の有効性を確かめるか、その時点のデフォルトを取得する。存在しない・削除済み・別アカウントの ID を指定した場合は `workspace_not_found`（REST API では400）を返す。すでに購読している場合は既存の所属を保ち、所属を変える場合は購読の変更 API か MCP の一括移動（8）を使う。OPML でのフォルダの取り込みと、Discord 以外の全購読・フォルダの書き出しは従来どおり。
8. **MCP で管理と一括移動を扱う。** ワークスペースの一覧・作成・改名・削除、指定フォルダ内の購読の一括移動の契約は [MCP サーバー](mcp.md)の 10 に従う。

## 理由

- **購読に所属を持たせる**と、フィードの取得と記事の受信箱を共有したまま、フォルダとは別に表示する範囲を選べる。
- **アカウントで選んだデフォルトを使う**と、購読のたびに所属先を選ぶ手間が減り、REST API、MCP、OPML、Discord で同じ既定先が使える。
- **操作時の購読 ID を送る**と、オフラインの間に選択や所属が変わっても、別の購読へ操作が広がらない。

## 検討した代替案

- **フォルダごとに所属させる**と、同じフォルダのフィードを用途ごとに分けるたびに、従来のフォルダ整理も変えることになる。
- **追加時に毎回明示指定を求める**と、アカウントに決めておいた購読先がある場合も選択が要る。
- **一括既読でワークスペース ID を送る**と、送信までに移動してきた購読も既読になる。

## 見直す条件

- MCP で記事をワークスペース別に検索・閲覧したいとき。
