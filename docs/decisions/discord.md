# Discord チャンネルの購読

- 状態：提案中
- 関連：[ユーザーと認証](accounts.md)、[仕事の流し方](jobs.md)、[差分同期](sync.md)、[記事の本文](content.md)、[画像の中継とサムネイル](images.md)

## 決定

1. **ブラウザの Integrations から Discord を接続する。** デプロイごとに Discord アプリと Bot を用意する。すでに Sendo にログインしている人が OAuth の `identify` で Discord アカウントを確認する。2 つのアカウントの結び付きだけを保存する。Bot の追加はサーバーを管理できる人が行う。
2. **1 チャンネルを 1 フィードとして購読する。** チャンネル URL を受け、接続した本人と Bot の両方が閲覧・履歴読み取りをできる場合だけ受け付ける。通常のテキストチャンネルとアナウンスチャンネルを対象にする。年齢制限付きのチャンネルは対象から外す。
3. **Discord の REST API を使い、購読したときに直近の投稿を最大 20 件取り込み、そのあとは新着を取得する。** 既存の定期ジョブで動かし、配布が済んだメッセージ ID を記録する。1 投稿を 1 記事として、テキスト、埋め込みの文字の部分、投稿者、投稿時刻、元投稿へのリンクを持つ。添付ファイル、埋め込みの画像・サムネイル・動画、元投稿の編集の反映は扱わない。
4. **Discord のフィードと記事は接続ごとに持つ。** 同じチャンネルの購読でも、別のユーザーに投稿を配らない。接続、連携解除、チャンネルの新規購読は Sendo のブラウザセッションで行う。Discord の購読は OPML に含めない。
5. **取得のたびにアクセスを確かめる。** Discord で閲覧権限を失ったことを検出した場合、購読を解除し、保存した記事をスター付きも含めて削除する。Sendo 側で個別に購読を解除した場合や、Discord との接続を解除した場合も同じ。クライアントには既存の差分同期で削除を伝える。
6. **テキストか埋め込みの文字がある投稿には、すべて本文を置く。** 本文は、フィードの本文と同じに置いて配る（[記事の本文](content.md)の 2〜7）。要約と同じ中身でも置く（[記事の本文](content.md)の 1 の例外）。
   - 本文は、テキストのあとに、埋め込みごとに作者の名前、タイトル（URL があればそのリンク）、説明、フィールドの名前と値、フッターの文字を並べる
   - Discord の Markdown は解釈せず、文字のまま出す。改行は保ち、http ／ https の URL はリンクにする
   - テキストのない投稿は、タイトルか説明のある最初の埋め込みから、タイトル（なければ説明の 1 行目）を記事のタイトルにし、説明を要約にする
   - 取り込み済みの投稿には、さかのぼって付けない
7. **フィードのアイコンは、Discord のサーバーのアイコンにする。** 取得のたびに読むサーバーの情報（5）から決め、アイコンを探す取得はしない（[画像の中継とサムネイル](images.md)の 8 の探し方と間隔は当てない）。サーバーにアイコンがなければ null。配り方は、ほかのフィードのアイコンと同じ（同じく 9）。

## 理由

- Bot の設置とチャンネルの権限を Discord 側で管理できる。公開 RSS と扱いを分けることで、ある人の権限で取得した投稿が別の人の購読に入るのを防げる。
- 新着を定期取得する形なら、常時接続する仕組みを置かず、フィードの取得と同じジョブの仕組みで扱える。
- 購読したときに直近の投稿を取り込むと、公開フィードと同じく、最初から投稿のペースで取得の間隔が決まる（[仕事の流し方](jobs.md)の 7）。購読より後の投稿だけを対象にすると、最初の取得は必ず 0 件になり、間隔が上限の 1 日になる。購読できるのは本人が履歴を読めるチャンネルだけなので（2）、本人が読める範囲は広がらない。20 件あれば、間隔を決めるのに足り、受信箱を古い投稿で埋めない。
- 通知の Bot や Webhook は、中身を埋め込みだけで送ることが多い。埋め込みを捨てると、記事にタイトルも本文も残らない。
- Discord の投稿は認証が要るので、記事のページから本文を抜けない（[記事の本文](content.md)の B）。本文がないと、記事を開いたクライアントはページの本文を求めて必ず失敗するので、テキストだけの投稿にも本文を置く。
- 添付ファイルの URL には、Discord が期限付きの署名を付けるので、保存した URL があとで切れる。埋め込みの画像も、添付ファイルを指すことがある。文字の部分だけなら、保存したものが切れない。
- Discord の Markdown を変換すると、Discord の書き方の変化に追いつく必要がある。文字のままでも読める。
- サーバーの情報は、権限を確かめるために取得のたびに読んでいるので、アイコンのための取得が増えない。チャンネルの URL は認証が要り、サイトのページからアイコンを探せない。

## 検討した代替案

- **埋め込みの文字を要約にだけ入れる**：本文を置かずに済むが、クライアントは本文のない記事として、ページの本文を求めて失敗する。
- **埋め込みの画像も本文に入れる**：見た目は Discord に近づくが、添付ファイルを指す画像は、上の理由で URL が切れる。外の画像だけを選んで入れる区別は、まだ要らない。

## 見直す条件

- 画像や添付ファイルだけの投稿が多く、記事として読めないことが目立ったとき。
