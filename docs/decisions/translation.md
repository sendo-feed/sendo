# 記事の翻訳

- 状態：提案中
- 関連：[記事の言語判定](article-language.md)、[記事の本文](content.md)、[差分同期](sync.md)、[仕事の流し方](jobs.md)、[保存容量と古い記事の片付け](retention.md)、[コンテナ版](container.md)、[Discord チャンネルの購読](discord.md)

日本語以外の記事を、Claude API（Anthropic の Claude Platform）で日本語に訳す。訳す先は日本語だけ。訳文は reader に配り、MCP、Google Reader API、REST の記事一覧では返さない。同じ元記事が届いたら、訳を写して使い回し、同じ原文をなるべく重ねて訳さない。

## 決定

### 何を訳すか

1. **記事ごとに 1 回だけ、訳すかどうかを決めて、訳文の行を作る。** 行のある記事は、二度と決め直さない（判定の版を上げて判定し直しても）。
   - 決めるのは、記事の言語の判定が、フィードの本文（なければタイトル・要約）とページの本文の両方で済んだとき（ページを抜けなかった記事と URL のない記事は、フィードの本文かタイトル・要約の判定のあと）。または、取り込んでから 1 時間たって、少なくとも 1 つの入力元の判定が済んだとき
   - 主言語は、[記事の言語判定](article-language.md)の結果のうち、状態が `detected` か `provisional` のものを、入力元 `page`、`feed`、`metadata` の順に探して使う
   - 主言語が日本語でなければ `queued`（4 で自動で訳す）。判定はあるが使える結果がなければ（どれも `und`）、`untranslated`（求めたときだけ訳す）。日本語なら `skipped`（配らず、訳さない）
   - 決めるのは、API キーがあり（15）、取り込んでから 1 日以内で、誰かの受信箱にある記事だけ。1 日たっても判定のない記事と、それより前に取り込んだ記事には、行を作らず、訳さない
   - 決める仕事は、その記事の言語の判定を保存したときと、ページを抜けなかったと記録したとき（[記事の本文](content.md)の 14）に、その記事について積む（[仕事の流し方](jobs.md)の 13）。5 分おきの定期実行も、まだ決めていない記事（抜けなかったことを記録できなかった記事、取り込んでから 1 時間たった記事を含む）を拾って決める。同じ記事の仕事が重なっても、行を作る文の中でまだ行がないことを確かめるので、1 回しか作らない。容量が足りず行を作れなかった記事は、取り込んでから 1 日のあいだ、定期実行がまた試す
2. **Discord の投稿は訳さない。** 行を作らず、外へ送らない（[Discord チャンネルの購読](discord.md)）。ほかのフィードは、公開かどうかを見分けずに対象にする。
3. **訳すのは、タイトル、要約、本文。** 本文は、訳すときにページの本文が抜けていればそれ（[記事の本文](content.md)の 10）、なければフィードの本文（同じく 1）。訳し直しで本文を選ぶ決まりは 6。
   - 本文がない記事、本文から送る文（10 の断片）の合計が 60,000 文字（Unicode の文字）を超える記事、訳した本文をサニタイズして 256KB を超える記事は、本文を置かず、タイトルと要約だけを訳す
   - 訳したあとでページの本文が抜けても、訳し直さない

### いつ訳すか

4. **`queued` の記事は、Message Batches API でまとめて訳す。** 5 分おきの定期実行で、次を行う。
   - 送る：`queued` で印のない行を 100 件まで、同じ文で送る印（このバッチの印と時刻）を付けて取り、1 つのバッチにして送る。同じ元記事の訳を写せる部分は送らずに結果を書く文で写し、すべて写せる行は送らない。同じ元記事の行がバッチの中にある行は取らない（16）。`custom_id` は記事の ID。送れたらバッチの ID を書き留める。印を付けてから 1 時間たってもバッチの ID がない行は、印を外して待ちに戻す（バッチを作った直後に落ちると 2 回払うことがあるが、受け入れる）
   - 見にいく：バッチの ID のある印を、古い順に 10 個まで見にいく。見にいけなかったとき（時間切れ、5xx）は印を残し、次の定期実行で見直す。終わっていれば結果を書く
   - 結果を書く文の中で、記事があること、行がそのバッチの印を持ち、まだ訳文がないことを確かめる。合わなければ捨てる。訳文を書いたら印を外す
   - `errored` ／ `expired` ／ `canceled` の記事と、もう見られない（404）バッチの記事は、同じ文で印を確かめて外し、回数を 8 のとおり数える。行が `queued` なら待ちのままにし、3 回目も訳せなかった記事と、拒否（`refusal`）された記事は `untranslated` にする。行が `translating`（その場の翻訳の最中）なら、状態と始めた時刻は変えない
5. **`queued` か `untranslated` の記事は、読む人が求めたときだけ、その場で訳す。** 開いただけでは訳さない。
   - 求めを受けたら、同じ文で、状態を確かめて `translating` にし、始めた時刻を書く。それから仕事を積み、202 を返す。訳し終えたことは差分同期で届ける（[差分同期](sync.md)の 10）
   - 同じ元記事の訳を写せる部分は送らずに結果を書く文で写し、残りだけを送る。すべて写せたら呼ばない（16）
   - 通常の Messages API にストリーミングで送る。拒否されたら、拒否の種類に応じて Anthropic が選ぶ代わりのモデルで訳させる（server-side fallbacks。バッチでは使えない）
   - 呼ぶ前と結果を書く文の中で、行が `translating` で、始めた時刻が仕事を積んだときのものと同じことを確かめる。合わなければ、呼ばずに（書かずに）やめる
   - 訳せたら、同じ文でバッチの印を外して `translated` にする。訳せなければ `untranslated` にする。`untranslated` の記事は、求めればまた訳す
6. **`translated` の記事は、読む人の求めで、1 回だけ Opus で訳し直す。** 訳し直したかどうかの印を行に持ち、印のある記事は訳し直さない。
   - 求めを受けたら、同じ文で、`translated` で印のないことを確かめて `translating` にし、始めた時刻を書く。もとの訳文は、訳し直した訳文が入るまで残す。呼ぶ前と書くときに 5 と同じく確かめる
   - 訳し直した訳文で全員分を置き換え、印を付けて `translated` に戻す。同じ元記事のほかの記事にも、置き換えられるものに写す（16）。失敗したら、もとの訳文のまま `translated` に戻す（印は付けない）
   - もとの訳文に本文があれば、同じ出どころ（`feed` ／ `page`）の本文を訳し直す。それでも 3 で本文を置かない条件に当たる（本文がない、送る文が 60,000 文字を超える、組み立てた本文が 256KB を超える）ときは失敗にする。仕事の中で、呼ぶ前に分かれば呼ばず、受け取ったあとで分かれば呼び直さない（8）
   - もとの訳文に本文がなければ、3 のとおりに本文を選ぶ。本文を置けなくても失敗にせず、タイトルと要約だけを訳し直す
7. **止まった `translating` は戻す。** 5 分おきの定期実行が、始めてから 1 時間を過ぎた `translating` を、訳文があれば `translated`、なければ `untranslated` に戻す。1 時間は、その場の翻訳の仕事が生きうる長さ（9 の 10 分を 3 回と、借りの期限）より長い。キーがなくても戻す。
8. **待てば通る失敗は回数に数えず、その場の翻訳では、やり直しても通らない失敗をやり直さない。**
   - バッチの回数は、結果が返った記事について数える。`errored` のうち一時的な種類（429、529、5xx の `api_error` ／ `overloaded_error`）と、9 でモデルを外すときの要求の形の誤りは数えない。`expired` ／ `canceled` と、もう見られないバッチ（4 の 404）は数える
   - バッチでは、容量の不足（12）、認証の失敗、利用上限のとき、送らずに待ちのまま次の定期実行に回す
   - その場の翻訳と訳し直しでは、[仕事の流し方](jobs.md)の 5 のとおり合わせて 3 回まで呼び、それでも通らなければ 5、6 の失敗にする
   - ただし、やり直しても通らない失敗は、受けたその回で 5、6 の失敗にする。要求の形の誤り（400）、認証の失敗（401）、権限の不足（403）、モデルの名前の誤り（404）、代わりのモデル（5）でも拒否されたもの、上限で切れた応答と読めない応答（9）、訳し直しで本文を置けないもの（6）。400 は、これとは別に、9 でモデルを外すかの判断にも数える

### どう訳すか

9. **通常はその時点で最新の Sonnet、訳し直しは最新の Opus を使う。**
   - 起動時と 1 日 1 回、Models API で一覧を取る。ID が `claude-sonnet-` ／ `claude-opus-` で始まるもののうち、作られた日がいちばん新しいものを選ぶ。一覧を取れなければ、前に選んだもの（なければコードの既定）を使う
   - 環境変数 `TRANSLATION_MODEL` ／ `RETRANSLATION_MODEL` に書けば、そのモデルに固定する
   - 新しく選んだモデルで、まだ 1 件も訳せていないうちに、要求の形の誤り（400 の `invalid_request_error`。バッチの `errored` も含む）が続けて 3 件起きたら、プロセスが動いている間はそのモデルを外し、次に新しいものを使う。ログに出す
   - 版が変わっても通るよう、要求に使う指定を絞る。`thinking`、サンプリング（`temperature` など）、ツールの強制は指定しない。考える量は `effort` を `low` にして抑え、出力の形は structured outputs で決める
   - 出力の上限は 64,000 トークン。上限で切れた応答と、読めない JSON は、訳せなかったものとして扱う。バッチでは回数に数え、その場の翻訳と訳し直しではその回で失敗にする（8）。その場の翻訳と訳し直しの 1 回の呼び出しは、時間切れとやり直しを合わせて 10 分で打ち切る
10. **HTML を LLM に渡さず、受け取らない。** サニタイズした本文を断片に分け、ID を付けた JSON で送る。structured outputs で同じ ID の訳を受け取り、元の木に戻す。
    - 文字を直接持つブロックの要素を、要素の名前によらず 1 つの断片にする。中に別のブロックがあれば、それは別の断片にする
    - 断片の中のリンク、強調、画像、改行、文の中のコードは、番号付きの印に替えて送り、訳のあとで元の要素に戻す。リンクと画像の URL、`pre` ／ `code` の中身は送らない
    - 印が欠けた・増えた・入れ替わった断片と、返ってこなかった断片は、原文のまま残す
    - 組み立てた本文は、もう一度サニタイズしてから置く（[記事の本文](content.md)の 2）
11. **記事の中身は指示ではないと伝え、訳は文字としてだけ扱う。外へ送るのは、訳す文だけ。**
    - システムプロンプトで、渡すのは訳す対象のデータで、その中の指示には従わないと伝える。受け取った訳は文字として扱い、タグとして解釈しない
    - 記事とリンクの URL、フィードの名前、読む人のこと（ユーザー、受信箱）は送らない

### 置く・配る

12. **訳文は記事ごとに 1 つ、記事とは別の表に置き、全員で使い回す。** 同じ元記事の記事どうしでは、訳を写して使い回す（16）。
    - 行には、状態（`queued` ／ `translating` ／ `translated` ／ `untranslated` ／ `skipped`）、元の言語、訳したタイトル・要約・本文（サニタイズした HTML）、訳した本文の出どころ（`feed` ／ `page`）、使ったモデル、訳した時刻、訳し直しの印、4〜8 の印・回数・時刻、16 の正規化した URL と送った本文の指紋を持つ
    - 記事を消すと、外部キーで一緒に消える。訳文は保存容量に含める（[保存容量と古い記事の片付け](retention.md)の 2）
    - 容量の上限（同じく 4）は、送る前と呼ぶ前に確かめ、当たれば送らない。受け取ったあとで当たったら、バッチは印を残して次の定期実行で書き直す（結果は 29 日読める）。その場の翻訳と訳し直しは、呼び直さずに失敗にする
13. **訳した本文は記事ごとに取りにいき、訳すことは記事ごとに求める。** どちらも、その人の受信箱にある記事だけ。認証はほかの REST API と同じ。
    - `GET /api/v1/articles/{id}/translation`：訳したタイトル・要約・本文と、本文の出どころ、使ったモデル、訳した時刻を返す。訳文がなければ 404。本文は返すときにもう一度サニタイズし、画像を中継の URL に書き換える（[記事の本文](content.md)の 2、7）
    - `POST /api/v1/articles/{id}/translation`：その場の翻訳（5）と訳し直し（6。本文で指定する）を求める。受け付けたら 202。断るときのコードは、`translation_unavailable`（API キーがない）、`translation_not_supported`（行がないか `skipped`）、`translation_exists`（その場の翻訳を求めたが、`translated` か `translating`）、`retranslation_not_allowed`（訳し直しを求めたが、`translated` でないか、訳し直したあと）
14. **元の言語、翻訳の状態、訳したタイトル・要約、訳し直しの印、訳した時刻は、差分同期で配る**（[差分同期](sync.md)の 10）。行のない記事と `skipped` の記事には付けない。読む人の画面は、訳した時刻が変わったら、手元の訳した本文を取り直す。

### 動かす条件

15. **API キーがあるときだけ、行を作り、外へ送る。** キーは環境変数 `ANTHROPIC_API_KEY` で受ける（[コンテナ版](container.md)の 11）。
    - キーがなければ、1 で行を作らない。行がなければ状態も配らないので、読む人の画面は翻訳の表示と操作を出さない。機能の有無を返す API は持たない（[コンテナ版](container.md)の 3）
    - キーを外したあとも、作った行と訳文は残る。残った行への求めは `translation_unavailable` で断り、バッチは送らず、見にいかない。`queued` の記事は、キーを戻すまで待ちのまま
    - キーをログ、応答、エラーの表示に出さない
    - 費用の上限は、アプリでは持たず、Claude Platform の利用上限で決める

### 同じ元記事で使い回す

16. **同じ元記事（正規化した URL が同じ）の記事どうしで、訳を写して使い回し、同じ原文をなるべく重ねて送らない。** 訳文の行は記事ごとのまま（12）で、使い回す訳を、その記事の行に写す。フィードが同じか違うかは問わない。
    - 正規化：URL を WHATWG URL として読み、http ／ https のものだけを対象にする。元のスキームの既定のポートを除いてからスキームを `https` にし、ホストを小文字にし、ユーザー情報とフラグメントを除き、パスの末尾の `/` をすべて除く（パスが `/` だけなら残す）。クエリから計測用のパラメータ（名前が `utm_` で始まるもの（大文字と小文字を区別しない）、`fbclid`、`gclid`）を除き、残りの順は保つ。残りがなければ `?` ごと除く
    - 正規化した URL は、1 で行を作るときに行に書く。URL のない記事、http ／ https でない記事、正規化してパスが `/` だけでクエリのない記事（サイトの最初のページ。壊れたフィードで、すべての項目のリンクがそこを指すことがある）は書かず、使い回さない。この決まりより前に作った行も書かず、使い回さない
    - 写す元は、同じ正規化した URL を持つ `translated` の行。訳し直した行を先に、次に訳した時刻の新しい順に選ぶ
    - タイトル：写す元に訳したタイトルがあれば、原文の表記が違っても写す。写す先の原文にタイトルがなければ写さない
    - 要約：写す元のうち、原文の要約の文字が同じ行の訳した要約を写す
    - 本文：写す元のうち、送る本文の指紋が同じで、訳した本文のある行の訳した本文を写す（「本文なし」の記事を除き、指紋が同じでも訳した本文のない行しかなければ、本文は送る）。指紋は、3 で選んだ本文（サニタイズした HTML）の SHA-256 で、本文を送らない記事（本文がない、60,000 文字を超える）は「本文なし」として、訳した（写した）ときに行に書く（12）。訳し直し（6）では、訳し直しで選んだ本文の指紋に書き換える。指紋のない行（この決まりより前に訳した行）は、本文の写す元にも、訳し直しを広げる先（下）にもしない。訳した本文の出どころは、その記事が 3 で選んだものを書く
    - いつ写すか：送る前（4 のバッチ、5 のその場の翻訳）に、写せるものと送るものを分け、送るものだけを送る。写す分は、結果を書く文（4、5 と同じ条件を確かめる文）の中で、写す元をその文の中で選び直して一緒に書く。送る前には行に書かない。その文のときに写す元がなくなっていたら、訳したタイトル・要約は原文の文字を書き、訳した本文は置かない（10 の、返ってこなかった断片と同じく原文のまま読む。本文を写すと決めて送らなかった記事では、本文の訳がないまま `translated` になることを、まれとして受け入れる）
    - すべて写せる行は送らない。バッチでは、印を付けて取った行のうち、すべて写せる行は、印を外して `translated` にする文の中で写し、空のバッチは作らない。その場の翻訳では呼ばずに、5 の結果を書く文の中で写す。どちらも、その文の中で写す元がなくなっていたら書かない。バッチでは印を外して待ちに戻し、その場の翻訳では写さずに送り直す
    - 写した行の訳した時刻は、書いた時刻にする。使ったモデルは、送って訳したものがあればそのモデル、すべて写したなら本文（本文がなければタイトル）を写した元の行のモデルにする。本文（本文がなければタイトル）を訳し直した行から写したら、訳し直しの印も付ける。写した訳文では、1 つの訳文の中で部分ごとにモデルが混ざりうることを受け入れる
    - バッチは待つ：同じ正規化した URL の行がバッチの印を持っている間（結果を書けるまで）は、その記事をバッチで送らない。同じ定期実行でも、同じ正規化した URL の行は 1 つだけを、バッチで訳せなかった回数（8）の少ない順、次に決めた順で取る（訳せずに待ちに戻った行より、待っていた行を先に送る）。どちらも送る行を取る文の中で確かめる。先の行の訳文が書けたら、次の定期実行で写す（残りがあれば送る）。すべて写せる行も、送る行と同じく待つ。その場の翻訳の最中の行（バッチの印がない）は、待つ理由にしない
    - その場の翻訳は待たない（読む人が待っているため）。写せるものを写し、残りを呼ぶ。同じ元記事がバッチの中にあれば、2 回払うことがある
    - 訳し直し（6）：訳し直した行を書いたあと、同じ正規化した URL で、本文の指紋が同じ（どちらも「本文なし」を含む）`translated` で訳し直しの印のない行に、訳し直したタイトルと本文を写し、要約の文字が同じ行には要約も写して、訳した時刻・使ったモデル・訳し直しの印を、写す元と同じにする。ただし、本文（本文がなければタイトル）を置き換えられない行には写さず、印も付けない。写す先に訳した本文があるのに写す元に訳し直した本文がない（6 で本文を置けなかった）行と、両方に本文がなく、タイトルも写せない（上のタイトルの項）行がそれにあたる。置き換えられない行は、定期実行でも写す先に選ばない。写さなかった行は、読む人が自分で訳し直せる。1 行ずつ、写す元（訳し直しの印のある行）と写す先の条件を、写す文の中で確かめる。訳し直した直後に写し、5 分おきの定期実行も、写し損ねた行（途中で落ちた、容量に当たった、そのとき `translated` でなかった）に写し直す。`translated` でない行（待ち、バッチの中、その場の翻訳の最中）は、あとで結果を書くときに、訳し直した行を先に選んで写す
    - 写した訳も、その行の訳文として保存容量に数える（12）。容量の上限に当たった行には写さない。送って結果を書くバッチの行は 12 のとおり印を残して次の定期実行で書き直し、すべて写せる行は印を外して待ちに戻し、その場の翻訳は 12 のとおり失敗にする。訳し直しを写す先が上限に当たったら、その行には写さず、次の定期実行でまた試す。元の記事が消えても、写した訳は残る

## 理由

- **Anthropic の API をそのまま使う**：料金が半分になる Message Batches API と、出力の形を決める structured outputs は、OpenAI 互換の形では使えない。
- **自動はバッチ、その場は求めたときだけ**：日本語以外の記事をすべてバッチで訳す費用は、定価の半分×記事の数。開いた記事だけをその場で訳す費用は、定価×開いた数。開くのが半分より多ければバッチのほうが安く、少なくても、開いたときに訳文がもうあって待たずに読めることを選んだ。その場の翻訳を自動にしないのは、バッチを待てば半額で済む記事にまで定価を払わないため。
- **判定のあとすぐ決める**：外国語の記事に早くラベル（`EN · Queued` など）を出し、読む人が待てば訳されると分かるようにする。決めるのは何度動かしても同じ結果で、外へ送らないので、定期実行を待つ理由が薄い（[仕事の流し方](jobs.md)の理由）。
- **1 回だけ決め、日本語と決めたことも残す**：判定のたびに決め直すと、待ちから外す・もう一度入れる規則が要り、判定の版を上げたときに古い記事の費用が跳ねる。決めた印がないと、あとから届いた判定で決め直してしまう。ページの本文の判定まで待てば、ほとんどの記事は本文の言語で決まる。
- **最新のモデルを Models API で選ぶ**：モデルの名前は版ごとに固定で、「最新」を指す別名がない。sendo を更新しなくても新しい版を使える。版によって受け付ける指定が変わるので、要求を絞り、受け付けなければ前の版に戻る。1 件の 400 は記事の中身でも起きるので、まだ 1 件も訳せていないモデルで続いたときだけ外す。
- **HTML を渡さない**：HTML を訳させると、タグが崩れたり、記事に仕込まれた要素が訳に混じって返ったりする。断片と印にすれば、構造は sendo が組み立て、LLM の出力は文字にしかならない。
- **Discord を訳さない**：非公開のチャンネルのことがあり、読む人が知らないうちに外へ送らない。ほかのフィードは公開かどうかを見分けられないので、区別しない。
- **訳文を全員で使い回す**：訳文は読む人によらない。購読者が何人いても、1 つの記事の訳文は 1 つで済む。
- **同じ元記事で使い回す**：Hacker News や Lobsters のようなフィードは、同じ元記事を別々に配る。記事はフィードごとの行なので、記事ごとに訳すと、同じ元記事を何度も訳して払う。本文はどちらも同じ URL のページから抜くので、費用の大半を占める本文を何度も払うことになる。
- **URL で見分け、タイトルは表記が違っても写す**：同じ元記事は、同じ訳したタイトルで読めれば足りる。フィードによるタイトルの表記の差（末尾に CVE の番号を足すなど）は、訳したタイトルには出ないことを受け入れ、タイトルを訳す費用を省く。正規化は、表記の揺れ（スキーム、末尾の `/`、計測用のパラメータ）だけをそろえ、中身が変わりうるクエリは残す。
- **要約と本文は、原文が同じときだけ写す**：要約はフィードごとに中身が違い（コメントの数や、元記事へのリンクだけのものがある）、本文はページを抜いた時刻で変わりうる。原文の違う訳を写すと、原文と訳が食い違う。
- **行に写し、別の表を持たない**：訳文は記事ごとの行のまま、差分同期、取りにいく API、容量の数え方、記事を消したときの後始末を今のまま使える。写した分は容量を重ねて使うが、外へ送る費用より安い。写した訳文では部分ごとにモデルが混ざりうるが、同じ原文を重ねて払わないことを選ぶ。
- **写すのは結果を書く文の中だけ**：送る前に写した部分を書くと、まだ訳し終えていない行に訳文の一部が入り、結果を書く文の「まだ訳文がない」の確かめや、止まった `translating` を戻す決まり（7）とぶつかる。写す元も書く文の中で選び直せば、間に訳し直された訳や消えた記事を取り違えない。
- **指紋を行に持ち、ないものは使わない**：送った本文が分からない行を写す元や広げる先にすると、本文のある訳が本文のない訳で上書きされうる。本文の写す元を訳した本文のある行に限るのも同じ理由で、本文を置けなかった行から写すと、送れば置けたかもしれない本文の訳を持てない。そのため、訳した本文が 256KB を超えて置けなかった本文は、同じ元記事が届くたびに送ることになるが、まれとみて受け入れる。
- **バッチは結果を待ち、その場の翻訳は待たない**：バッチはもともと最大 24 時間かかるので、待っても読む人の待ちは大きく変わらず、本文を 2 回払わない。その場の翻訳は読む人が待っているので、2 回払うことがあっても待たせない。
- **サイトの最初のページは使い回さない**：壊れたフィードでは、すべての項目のリンクが最初のページを指し、別々の記事に同じ訳したタイトルが写ってしまう。
- **訳し直しを同じ元記事に広げる**：同じ原文の訳文は同じであるべきで、1 回の払いで、同じ元記事を読むすべての人の訳文を良くする。広げるのは 1 行ずつで、定期実行が写し損ねた行に写し直すので、途中で落ちたり、容量に当たったり、そのとき訳し終えていなかったりした行にも、あとで届く。本文（本文がなければタイトル）を置き換えられない行に写さないのは、6 と同じく、全員分の訳した本文を消したり、Sonnet のまま残った本文（本文がなければタイトル）に印を付けて二度と訳し直せなくしたりしないため。
- **本文に上限を置く**：その場の翻訳を、仕事の借りの期限（[仕事の流し方](jobs.md)の 1。15 分）の中で終える。60,000 文字の英文は、訳文がおよそ 2 万トークンで、数分で返る。
- **その場の翻訳は応答を待たせない**：長い記事では訳し終えるまで数分かかり、HTTP の応答として待たせられない。終わりは、ほかの変更と同じく差分同期と通知で届く。
- **訳し直しで訳文を減らさない**：訳し直しは品質を上げるために求めるもので、成功すれば印が付き、二度とできない。本文を置けないまま置き換えると、全員分の訳した本文が消え、もう取り戻せない。失敗にすれば、もとの訳文が残る。出どころを揃えるのは、あとから抜けたページの本文が上限を超えていると、何度求めても失敗するため。受け取ったあとで分かる失敗（256KB を超える）は、求めるたびに払うことになるが、同じ出どころから作ったもとの訳した本文は 256KB に収まっていたので、まれとみて受け入れる。
- **状態を同じ文で移し、始めた時刻で確かめる**：バッチの結果、その場の翻訳、訳し直しは、同じ記事に別々の時刻に書く。もとの状態と印、始めた時刻を書く文の中で確かめれば、遅れて返った結果や、戻したあとに終わった古い仕事が新しい訳文を上書きせず、2 人が同時に求めても 1 回しか払わない。払い済みのバッチの結果は、その場の翻訳の最中でも、まだ訳文がなければ書く。訳文のある行には書かないので、訳し直しを上書きしない。
- **待てば通る失敗を数えない**：混み合いや利用上限のあいだに回数を使い切ると、自動の翻訳が二度と戻らない。
- **やり直しても通らない失敗は、その場の翻訳ですぐ諦める**：要求の形、キー、権限、モデルの名前の誤りは、仕事のやり直し（1 分おき）の間には変わらず、何度呼んでも同じ答えになる。拒否や、上限で切れる応答・読めない応答も、同じ記事ではまた起きやすい（読めない応答は、structured outputs で形を決めているので、ほとんどが切れたときに起きる）。やり直すと、読む人は `translating` のまま数分待たされ、訳せないと分かるのが遅れる。キーやモデルの誤りで `queued` の記事が `untranslated` になると、自動の翻訳からは外れるが、直したあとに読む人がもう一度求めれば訳せる。

## 検討した代替案

- **OpenAI 互換のエンドポイントで、ほかの LLM と差し替える**：Batches と structured outputs が使えない。ほかの機能（要約など）の差し替えは、その機能を作るときに決める。
- **読む人が開いたときに、その場で自動で訳す**：外国語の記事の半分より多く開くなら高くつき、開くたびに待つ。
- **モデルを env だけで決め、既定は sendo の更新で替える**：試してから切り替えられるが、更新しないと古いまま。固定したいときのために env は残す。
- **HTML のまま訳させる**：プロンプトだけでは、タグの崩れと、記事の要素が混じるのを防げない。
- **Opus の訳文を、求めた人にだけ見せる**：人ごとのデータになり、同じ記事に何度も費用がかかる。
- **訳し直しで本文を置けなくても、本文なしで置き換える**：作りは簡単だが、訳した本文が消え、印が付くので取り戻せない。
- **訳し直しで本文を置けなければ、タイトルと要約だけを替え、もとの本文を残す**：訳文は減らないが、訳し直しの印が付くので、Sonnet のまま残った本文を二度と訳し直せない。
- **原文の文字のハッシュだけで引き、URL を見ない**：URL の正規化が要らず、URL のない記事や別の URL の同じ文にも効くが、表記の違うタイトルは別に訳す。
- **正規化した URL とタイトルの文字が同じときだけ、タイトルを写す**：訳したタイトルが原文と食い違わないが、フィードごとに表記が違うことが多く、タイトルは使い回せない。
- **バッチの結果を待たずに、同じ元記事も送る**：作りは簡単だが、先の結果が返る前に決まった記事（ほとんどの場合）では、本文を 2 回払う。
- **訳し直しは、求めた記事だけ**：置き換えの範囲が読む人に分かりやすいが、同じ元記事のほかの記事を良くするには、また払う。
- **使い回す訳を、キーで引ける別の表に置く**：重ねて置かずに済むが、記事が消えたときの後始末と、容量の数え方が増える。

## 見直す条件

- Anthropic が「最新」を指す別名を出したとき。新しい版で要求の形が変わり、前の版に戻ることが続くとき。
- 費用が利用上限に届くことが続くとき。フィードごとに翻訳を外す設定を足すか、自動の対象を絞るか、安いモデルに替える。
- 印が崩れて原文のまま残る断片が目立つとき。60,000 文字を超えて本文を訳せない記事が目立つとき。本文を置けずに訳し直しが失敗する記事や、同じ元記事の本文を置けずに重ねて送ることが目立つとき。
- 同じ正規化した URL で中身の違うページを返すサイト（末尾の `/` の有無で別のページなど）や、同じ URL を別の記事が指すフィード、写した訳したタイトルが原文と食い違って困ることが目立つとき。
- ページを抜いた時刻で中身が変わり、指紋が合わずに本文を重ねて払う記事が目立つとき。
- 件数や費用の上限をアプリで持つことになったとき。写した分は外へ送らないので、数え方を決め直す。
- 日本語以外への翻訳や、読む人ごとの訳す先が要るとき。
