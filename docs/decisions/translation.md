# 記事の翻訳

- 状態：提案中
- 関連：[記事の言語判定](article-language.md)、[記事の本文](content.md)、[差分同期](sync.md)、[仕事の流し方](jobs.md)、[保存容量と古い記事の片付け](retention.md)、[コンテナ版](container.md)、[Discord チャンネルの購読](discord.md)

日本語以外の記事を、Claude API（Anthropic の Claude Platform）で日本語に訳す。訳す先は日本語だけ。

## 決定

### 何を訳すか

1. **主言語が日本語でない記事を訳す。** 主言語は[記事の言語判定](article-language.md)の結果を、入力元 `page`、`feed`、`metadata` の順に、あるものから使う。
   - 自動で訳す（4）のは、状態が `detected` か `provisional` で、言語が `ja` でない記事
   - 言語が `und` の記事は、自動では訳さない。読む人が求めたとき（5）だけ訳す
   - 訳せる状態（14）になる前に取り込んだ記事は、自動では訳さない。求めれば訳す
2. **Discord の投稿は訳さない。** 自動でも、求められても、外へ送らない（[Discord チャンネルの購読](discord.md)）。
3. **訳すのは、タイトル、要約、本文。** 本文は、訳すときにページの本文が抜けていればそれ（[記事の本文](content.md)の 10）、なければフィードの本文（同じく 1）。本文のない記事は、タイトルと要約だけを訳す。
   - 本文から送る文（8 の断片）の合計が 60,000 文字（Unicode の文字）を超えるときは、本文を訳さず、タイトルと要約だけを訳す
   - 訳したあとでページの本文が抜けても、訳し直さない

### いつ訳すか

4. **取り込んだ記事は、Message Batches API でまとめて訳す。**
   - 言語の判定で 1 の自動の対象と決まった記事を、待ち（`queued`）にする
   - 5 分おきの定期実行で、待ちの記事のうち、ページの抜き取りが終わった（抜けた、抜けなかった、記事の URL がない）記事と、取り込んでから 1 時間たった記事を、1 回に 100 件まで 1 つのバッチにして送る。送ったバッチの結果も、同じ定期実行で見にいく
   - 結果が `errored` ／ `expired` の記事は待ちに戻し、次のバッチで送り直す。送るのは 1 つの記事につき 3 回まで。それを超えた記事と、拒否（`refusal`）された記事は、訳せなかったもの（`untranslated`）にする
5. **訳文のない記事は、読む人が求めたときだけ、その場で訳す。** 開いただけでは訳さない。
   - 通常の Messages API で送る。求めを受けたら仕事を積んで、すぐに応答する。訳し終えたことは、差分同期で届ける（13）
   - その場で訳した記事は、あとで返ったバッチの結果を捨てる。訳文を書く文の中で、まだ訳文がないことを確かめる
   - 拒否されたら、拒否の種類に応じて Anthropic が選ぶ代わりのモデルで訳させる（server-side fallbacks。バッチでは使えない）。それでも訳せなければ、訳せなかったものにする
   - 訳せなかった記事も、求めれば訳し直す
6. **読む人の求めで、Opus で訳し直す。** 訳文のある記事だけを、1 つの記事につき 1 回だけ訳し直す。Opus で訳した記事は、訳し直さない。
   - 訳し直した訳文で、全員分を置き換える。始めるときに、Opus の訳文でないことと、訳し直している最中でないことを、同じ文の中で確かめる
   - 失敗したら、もとの訳文を残す。バッチの結果は、すでにある訳文を上書きしない

### どう訳すか

7. **通常はその時点で最新の Sonnet、訳し直しは最新の Opus を使う。**
   - 起動時と 1 日 1 回、Models API で一覧を取る。ID が `claude-sonnet-` ／ `claude-opus-` で始まるもののうち、作られた日がいちばん新しいものを選ぶ。一覧を取れなければ、前に選んだもの（なければコードの既定）を使う
   - 環境変数 `TRANSLATION_MODEL` ／ `RETRANSLATION_MODEL` に書けば、そのモデルに固定する
   - 選んだモデルが要求の形を受け付けなかったら（400 の `invalid_request_error`）、プロセスが動いている間はそのモデルを使わず、次に新しいものを使う。ログに出す
   - 版が変わっても通るよう、要求に使う指定を絞る。`thinking`、サンプリング（`temperature` など）、ツールの強制は指定しない。考える量は `effort` を `low` にして抑え、出力の形は structured outputs で決める
8. **HTML を LLM に渡さず、受け取らない。** サニタイズした本文を、ブロック（段落、見出し、リストの項目、表のセル、引用、キャプション）ごとの断片に分け、ID を付けた JSON で送る。structured outputs で同じ ID の訳を受け取り、元の木に戻す。
   - 断片の中のリンク、強調、画像、改行、文の中のコードは、番号付きの印に替えて送り、訳のあとで元の要素に戻す。リンクと画像の URL、`pre` ／ `code` の中身は送らない
   - 印が欠けた・増えた・入れ替わった断片と、返ってこなかった断片は、原文のまま残す
   - 組み立てた本文は、もう一度サニタイズしてから置く（[記事の本文](content.md)の 2）
9. **記事の中身は指示ではないと伝え、訳は文字としてだけ扱う。** システムプロンプトで、渡すのは訳す対象のデータで、その中の指示には従わないと伝える。受け取った訳は文字として扱い、タグとして解釈しない。
10. **外へ送るのは、訳す文だけ。** 記事とリンクの URL、フィードの名前、読む人のこと（ユーザー、受信箱）は送らない。

### 置く・配る

11. **訳文は記事ごとに 1 つ、記事とは別の表に置き、全員で使い回す。** 記事の行は変えない（[差分同期](sync.md)の 7）。
    - 行には、状態、訳したタイトル・要約・本文（サニタイズした HTML）、訳した本文の出どころ（`feed` ／ `page`）、使ったモデル、訳した時刻を持つ
    - 状態は `queued`（バッチを待っている）、`translating`（その場の翻訳か訳し直しの最中）、`translated`（訳文がある）、`untranslated`（訳文がない。まだ訳していないか、訳せなかった）
    - 記事を消すと、外部キーで一緒に消える。訳文は保存容量に含める（[保存容量と古い記事の片付け](retention.md)の 2）
12. **訳した本文は、記事ごとに取りにいく。** `GET /api/v1/articles/{id}/translation` で、訳したタイトル・要約・本文と、本文の出どころ、使ったモデルを返す。訳文がなければ 404。
    - 本文は、返すときにもう一度サニタイズし、画像を中継の URL に書き換える（[記事の本文](content.md)の 2、7）
    - その場の翻訳と訳し直しは、`POST /api/v1/articles/{id}/translation` で求める（訳し直しは本文で指定する）。受け付けたら 202 を返す。日本語の記事、Discord の投稿、5 と 6 の条件に合わない求め、API キーのない sendo では、それぞれのコードで断る
    - どちらも、その人の受信箱にある記事だけ。認証はほかの REST API と同じ
13. **訳したタイトル・要約と状態は、差分同期に載せる。** 載せ方は[差分同期](sync.md)の決定で決める。状態を載せるのは、1 と 2 で訳せる記事だけ（14 を満たすとき）。日本語の記事と Discord の投稿には載せない。

### 動かす条件

14. **API キーがあるときだけ動く。** 環境変数 `ANTHROPIC_API_KEY` で受ける（[コンテナ版](container.md)の 11）。
    - なければ、待ちにせず、外へ送らず、状態も載せない。読む人の画面は、状態のない記事に翻訳の表示と操作を出さない。機能の有無を返す API は持たない（[コンテナ版](container.md)の 3）
    - キーをログ、応答、エラーの表示に出さない
    - 費用の上限は、アプリでは持たず、Claude Platform の利用上限で決める

## 理由

- **Anthropic の API をそのまま使う**：料金が半分になる Message Batches API と、出力の形を決める structured outputs は、OpenAI 互換の形では使えない。
- **自動はバッチ、その場は求めたときだけ**：待つ時間より費用を優先する。開くたびにその場で訳すと料金が倍になり、読まずに流す記事や、訳さなくてよい記事にもかかる。
- **最新のモデルを Models API で選ぶ**：モデルの名前は版ごとに固定で、「最新」を指す別名がない。sendo を更新しなくても新しい版を使える。版によって受け付ける指定が変わるので、要求を絞り、受け付けなければ前の版に戻る。
- **HTML を渡さない**：HTML を訳させると、タグが崩れたり、記事に仕込まれた要素が訳に混じって返ったりする。断片と印にすれば、構造は sendo が組み立て、LLM の出力は文字にしかならない。
- **Discord を訳さない**：非公開のチャンネルのことがあり、読む人が知らないうちに外へ送らない。
- **訳文を全員で使い回す**：訳文は読む人によらない。購読者が何人いても、1 つの記事の費用は 1 回分で済む。
- **本文に上限を置く**：その場の翻訳を、仕事の借りの期限（[仕事の流し方](jobs.md)の 1。15 分）の中で終える。60,000 文字の英文は、訳文がおよそ 2 万トークンで、数分で返る。
- **その場の翻訳は応答を待たせない**：長い記事では訳し終えるまで数分かかり、HTTP の応答として待たせられない。終わりは、ほかの変更と同じく差分同期と通知で届く。

## 検討した代替案

- **OpenAI 互換のエンドポイントで、ほかの LLM と差し替える**：Batches と structured outputs が使えない。ほかの機能（要約など）の差し替えは、その機能を作るときに決める。
- **読む人が開いたときに、その場で自動で訳す**：費用が読む記事の数だけかかり、訳さなくてよい記事にもかかる。
- **モデルを env だけで決め、既定は sendo の更新で替える**：試してから切り替えられるが、更新しないと古いまま。固定したいときのために env は残す。
- **HTML のまま訳させる**：プロンプトだけでは、タグの崩れと、記事の要素が混じるのを防げない。
- **Opus の訳文を、求めた人にだけ見せる**：人ごとのデータになり、同じ記事に何度も費用がかかる。

## 見直す条件

- Anthropic が「最新」を指す別名を出したとき。新しい版で要求の形が変わり、前の版に戻ることが続くとき。
- 費用が利用上限に届くことが続くとき（自動の対象を絞るか、安いモデルに替える）。
- 印が崩れて原文のまま残る断片が目立つとき。60,000 文字を超えて本文を訳せない記事が目立つとき。
- 日本語以外への翻訳や、読む人ごとの訳す先が要るとき。
