# 記事のキーワード検索

- 状態：提案中
- 関連：[テックスタック](tech-stack.md)、[記事の本文](content.md)、[保存容量と古い記事の片付け](retention.md)、[MCP サーバー](mcp.md)

購読した記事をキーワードで探せるようにする。たとえば、MCP から既読時刻を先月に絞って、本文または記事名に「.NET」を含む記事を探す。

## 決定

1. **両方の版で SQLite FTS5 の trigram を使う。** 索引は SQLite の緩衝層に置く。入力はキーワードの文字列として扱い、FTS の構文として解釈させない。3 文字未満は受信箱の検索対象に文字列の部分一致をかける。
2. **タイトル、要約、保存済みの本文を対象にする。** ページから抽出済みの本文があれば使い、なければフィード本文を使う。本文はプレーンテキストの先頭 20,000 文字までを索引に載せる。本文がない記事もタイトルと要約を載せる。索引をまだ作っていない記事は、タイトルと要約で検索できる。
3. **索引は作り直せる派生データにする。** 新規記事や本文が変わった記事を索引待ちに入れ、既存記事も位置を記録しながら少しずつ加える。索引のジョブは 10 分に 1 回、最大 10 件を処理する。UTC の 1 日あたりの索引追加・更新は、再送を含め 1,500 件までとし、書き込みと同じ文で上限を守る。本文の読み出しに失敗したら、再試行を少し後へ回してほかの記事を処理する。元の記事が消えたら索引も消す。索引の容量は、格納するテキストの UTF-8 バイト数の 8 倍に 512 バイトを加えて見積もり、記事の保存容量に含める。書き込み後の使用量が上限の 80% を超える場合は、索引の書き込みを後回しにする（[費用の見積もり](../cost.md#記事のキーワード検索の見積もり)）。
4. **MCP の `search_articles` は認証済みユーザーの受信箱だけを読む。** `list_articles` と同じ既読状態・スター・フィード・フォルダ・期間の絞り込みを使う。公開日時か既読日時の新しい順でページ送りし、結果は記事と、マッチした箇所のプレーンテキストの抜粋を返す。
5. **D1 のバックアップは Time Travel の範囲と復元経路を意識する。** FTS5 を含む SQL エクスポートは SQLite CLI 向けで、同じエクスポートを D1 へそのままインポートできない。索引を除いた元データから移行・復元した環境では、定期ジョブで索引を再構築する。

## 理由

- trigram なら分かち書きなしで日本語の部分一致を使える。3 文字に満たない語は別の条件で拾える。
- 検索の結果に記事 ID と抜粋があると、Claude が本文を取る対象を選べる。
- 本文と容量の境界をそろえ、索引を作る作業で新着の取得が止まりにくくする。
